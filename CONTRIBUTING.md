# Contributing to End-to-End Data Engineering Project

Thank you for your interest in contributing to this data engineering project! This document provides guidelines for contributing to the repository.

## 🚀 Getting Started

1. **Fork the repository** on GitHub
2. **Clone your fork** locally:
   ```bash
   git clone https://github.com/YOUR_USERNAME/end-to-end-data-engineering-project-4413618.git
   cd end-to-end-data-engineering-project-4413618
   ```
3. **Set up development environment** following the README instructions
4. **Create a new branch** for your feature:
   ```bash
   git checkout -b feature/your-feature-name
   ```

## 📝 Development Guidelines

### Code Style
- Follow Python PEP 8 style guidelines
- Use meaningful variable and function names
- Add docstrings to functions and classes
- Keep functions focused and small

### SQL Style (dbt)
- Use consistent indentation (2 spaces)
- Use descriptive column aliases
- Add comments for complex logic
- Follow dbt naming conventions

### Testing
- Write tests for new functionality
- Ensure existing tests pass
- Test both success and failure scenarios

## 🔄 Pull Request Process

1. **Make your changes** following the guidelines above
2. **Test your changes** thoroughly
3. **Update documentation** if needed
4. **Commit your changes** with descriptive messages:
   ```bash
   git commit -m "Add feature: brief description"
   ```
5. **Push to your fork**:
   ```bash
   git push origin feature/your-feature-name
   ```
6. **Create a Pull Request** on GitHub

### Pull Request Guidelines
- Provide a clear description of changes
- Reference any related issues
- Include screenshots for UI changes
- Ensure all checks pass

## 🐛 Reporting Issues

When reporting issues, please include:
- **Description** of the problem
- **Steps to reproduce** the issue
- **Expected behavior** vs actual behavior
- **Environment details** (OS, Python version, etc.)
- **Error messages** or logs if applicable

## 📋 Issue Labels

- `bug` - Something isn't working
- `enhancement` - New feature or request
- `documentation` - Improvements to documentation
- `good first issue` - Good for newcomers
- `help wanted` - Extra attention is needed

## 🎯 Areas for Contribution

- **New dbt models** for additional analytics
- **Data quality tests** and validations
- **Documentation improvements**
- **Performance optimizations**
- **Additional data sources**
- **Monitoring and alerting**

## 📞 Questions?

If you have questions about contributing, please:
- Open an issue with the `question` label
- Check existing issues and discussions
- Review the documentation

Thank you for contributing! 🎉
